# Data

This project uses Kaggle's public
["Store Sales - Time Series Forecasting"](https://www.kaggle.com/competitions/store-sales-time-series-forecasting/data)
competition dataset (Corporación Favorita, Ecuador).

## ⚠️ Redistribution constraint — never commit the raw data

This repository is **public**, and redistributing the competition dataset would violate Kaggle's
competition rules. The raw files therefore live in a **gitignored** directory and must never be
committed — not the CSVs, not the original `.zip`, not even a small extract. Tests and CI instead
use a **synthetic** fixture (`tests/fixtures/sample_train.csv`, generated by
`scripts/generate_test_fixture.py`) that contains no Kaggle data.

Gitignored locations:

| Path | Contents |
|---|---|
| `eda/data/store-sales-time-series-forecasting/` | Raw Kaggle CSVs (`settings.DATA_RAW_DIR`) |
| `eda/data/*.zip` | The original competition archive, if downloaded manually |
| `data/processed/` | Derived feature frames (P0.4) — regenerable |

## Populating the raw-data directory

**Option A — Kaggle API (preferred)**

1. Accept the competition rules on its Kaggle page (the API returns 403 otherwise).
2. Create an API token at <https://www.kaggle.com/settings> → API, then copy `.env.example` to
   `.env` and set `KAGGLE_USERNAME` + `KAGGLE_KEY` (or `KAGGLE_API_TOKEN` for newer tokens).
3. Run:

   ```bash
   uv run python -m forecasting_platform.data.download   # or: make data
   ```

**Option B — manual download (fallback)**

1. Download the zip from the competition's
   [data page](https://www.kaggle.com/competitions/store-sales-time-series-forecasting/data).
2. Unzip it into `eda/data/store-sales-time-series-forecasting/`.

Either way, then validate:

```bash
uv run python -m forecasting_platform.data.validate   # or: make validate-data
```

It should end with `all checks passed`. To keep the files elsewhere, set `DATA_RAW_DIR` in `.env`.

## Files and schema

Train data spans **2013-01-01 to 2017-08-15** (daily), covering 54 stores × 33 product families =
1782 `(store_nbr, family)` series (53 of which are structurally all-zero).

| File | Grain | Key columns |
|---|---|---|
| `train.csv` | date × store_nbr × family | `id` (int), `date` (YYYY-MM-DD), `store_nbr` (int, 1–54), `family` (str, 33 categories), `sales` (float — the forecast target; fractional for goods sold by weight), `onpromotion` (int — items in that family on promotion at that store that day) |
| `stores.csv` | store_nbr | `store_nbr`, `city`, `state`, `type` (A–E), `cluster` (1–17) |
| `oil.csv` | date | `date`, `dcoilwtico` (daily WTI oil price; gaps on non-trading days — forward-filled in feature engineering) |
| `holidays_events.csv` | date (possibly several rows per date) | `date`, `type` (`Holiday`/`Transfer`/`Additional`/`Bridge`/`Work Day`/`Event`), `locale` (`National`/`Regional`/`Local`), `locale_name`, `description`, `transferred` (bool — if true, the holiday was moved to the paired `Transfer` row's date and this date is a normal working day) |
| `transactions.csv` | date × store_nbr | `date`, `store_nbr`, `transactions` (total store transactions that day) |
| `test.csv`, `sample_submission.csv` | — | Kaggle's official scoring files. **Not used**: we evaluate on our own holdout (the last 28 days of `train.csv`) — see `PLAN.md` section 3.2. |
